# MissionGuard 参赛竞争力审查与选题决策

审查日期：2026-09-24。目的：选择剩余时间内最值得投入的参赛方向。基于当前代码、已有测试记录、活动官网和竞品官方资料；不构成独立安全审计，也不代表掌握全部参赛项目。

## 决策

推荐继续使用 MissionGuard 的合约基础，收窄为 **AI 任务采购与费用凭证**，主报“身份 / 信任 / AI 基础设施”，以消费支付场景展示价值。

一句话：**给 AI 团队一笔任务预算，交付结果时附上可核对的采购账单；某个执行分支失控时，能停止该分支并收回未使用预算。**

当前版本不建议原样提交。应保留经过本地测试的资金约束与授权逻辑，把投入重点从攻击按钮和页面包装转向真实任务、可检查的结果和 Fuji 交易证据。这是对完成度、展示效果和交付风险的综合判断，不是获奖概率计算。

## 必须修正的技术与宣传问题

1. **错误分类不正确。** `components/chain-panel.tsx:466` 捕获所有 `simulateContract` 异常后，统一显示“合约模拟已拒绝”。RPC 超时、网络故障也会进入这一分支。应仅对已解码、符合预期的合约策略错误显示“策略拒绝”；其他情况显示“未能验证 / 网络错误”。这是一项演示可信度问题，不等于已发现合约盗币漏洞。
2. **重放保护的边界。** 当前 `requestId` 防止同一个 ID 再次执行，不会识别换一个 ID 的同一笔语义采购。服务端需要以任务和订单绑定幂等结果。不得宣传为“AI 永远不会重复购买”。
3. **任务哈希的边界。** `specHash` 记录承诺，不能证明任务完成、报告正确或商家诚实。新增结果哈希也不改变这一点。
4. **付款和服务交付的边界。** 当前合约转账不保证服务会交付。演示服务必须支持按已确认付款恢复结果获取，不能把转账成功直接标成服务完成；恶意商家履约问题不在当前合约保证范围内。
5. **撤销的边界。** 已确认撤销会阻止受影响权限后续使用，不能保证赶在待确认付款之前执行。允许范围内的恶意支出仍可能发生。
6. **Agent 的边界。** 目前为确定性脚本，不应包装成真实自主模型。接入模型后也只能让模型提出有限工具请求，不向模型提供所有者私钥。

## 竞争定位需要调整

- MetaMask 官方资料已经描述链式委托、权限收窄，以及撤销上游使下游失效。因此，不能把“层级授权 + 子树撤销”宣称为独创。
- Coinbase Agentic Wallets 官方产品已提供会话和单笔支出限额，因此“给 Agent 限额”本身不足以构成鲜明选题。
- 已有公开的 x402 Intent Firewall 项目展示限额、收款方约束和暂停等功能。这里只确认其公开说明，未独立验证代码安全、链上行为或获奖情况。

来源：[MetaMask Delegation Toolkit](https://metamask.io/news/what-is-the-delegation-toolkit-and-what-can-you-build-with-it)、[Coinbase Agentic Wallets](https://www.coinbase.com/developer-platform/products/agentic-wallets)、[x402 Intent Firewall 项目](https://github.com/Venkat5599/x402-Intent-Firewall)。

可争取的差异是：把一个明确任务的预算、子任务权限、服务采购、输出文件和花费凭证放在同一个流程里，并提供可复查的异常处理演示。这属于产品整合与可用性主张，不是未经证明的协议首创。

## 备选方向比较

以下是针对当前团队资产和剩余时间的判断，未做市场规模或用户付费验证。

| 方向 | 优势 | 主要缺点 | 决策 |
| --- | --- | --- | --- |
| 原版通用 AI 支付防火墙 | 当前实现最多 | 与现有钱包和权限产品重叠；任务价值薄弱 | 不按原定位提交 |
| AI 任务采购与费用凭证 | 复用合约；结果和支出一同展示；异常分支可形成有记忆点的演示 | 仍需证明真实需求，补任务与服务闭环 | 首选 |
| 开源悬赏 / 里程碑托管 | 使用场景容易理解 | 验收争议、仲裁与用户来源都是新工作；原有实现复用有限 | 本次不切换 |
| 活动押金 / 到场退款 | 场景直观，产品可较快完成 | 需要真实活动方，现场验证与防作弊还未建立 | 有现成合作方时再考虑 |
| 新的 RWA、收益策略或跨链平台 | 可扩展叙事 | 新合约、外部依赖、验证和演示风险过大 | 排除本次范围 |

## 推荐的唯一主场景

用户：正在开发多 Agent 应用、需要让 Agent 按任务调用收费工具的开发者。

任务示例：**生成一个 Avalanche 合约近期活动简报，包含可回查的数据来源、区块或时间范围，以及费用清单。** 只做描述性数据分析，不包装成投资建议或安全审计。

演示使用无价值的 DemoUSD 测试代币。数据服务可由项目自建，并清楚标注“演示服务”；必须真正从公开来源读取数据、计算并交付结果，不伪装成已合作商家或付费客户。模型使用可用的免费或本地方案，接入条件尚待验证。

### 三分钟展示链路

1. 打开任务单：输入任务与预算，看到允许使用的服务、时间边界和权限树。
2. 执行：研究 Agent 委派数据子任务，另一个独立分支进行核对；服务返回真实数据，生成带来源的简报。
3. 费用：每个服务步骤显示订单、结果状态和已确认 Fuji 付款链接；成功付款与交付状态分开呈现。
4. 异常：明确标注为注入的攻击测试，让一个分支尝试向未批准收款方付款；展示具体拒绝原因。随后撤销该分支，证明其下级失效，而独立分支仍可完成合法工作。
5. 结束：生成最终结果和费用清单，展示终止任务后的剩余预算退款。

撤销由用户操作触发；不宣称系统能识别一切恶意意图。固定脚本回放可以保留，但须与实时模型执行、只读链上证据分开标注。

## 改造优先级与验收

### P0：提交前必须完成

- 修复错误分类；RPC 失败不能再计为拦截成功。
- 一个真实任务从输入到最终文件完成，记录来源、读取时间和数据范围。
- 服务订单具备幂等与恢复机制；同一付款重试取结果不会二次收费。
- 完成 Fuji 部署、有效付款、分支撤销和退款，保存可核对的交易回执。
- 网页提供真实父子授权与分支撤销入口，明确显示共享预算约束。
- 首页直接展示结果和费用证据。评委可免连接钱包查看已完成案例；自己执行流程另设入口。
- 完成一次真实浏览器与钱包端到端验证，录制三分钟视频。失败场景和模拟内容如实标注。

### P1：闭环稳定后再做

- 提供一个最小可运行的开发者接入示例，覆盖创建任务、授权、采购、查询、撤销、退款，而不是只暴露签名结构。
- 记录实际 Fuji 确认耗时、Gas 和总调用成本；明确测试环境，不引用主网承诺替代测量。
- 请两位独立开发者实际尝试，记录卡点并改进。此为目标，目前没有完成，也不会自行向外部联系人发送邀请。
- 改写幻灯片为“问题—实际任务—异常恢复—实现证据—适用边界”，删除首创或过度安全承诺。

### 取消本轮扩张

不另起自己的 L1、多链桥、代币经济或商家市场。当前不是 x402 实现；只有完成真正兼容并验证的支付流程，才可添加该标签。不要为了关键词堆标准。
